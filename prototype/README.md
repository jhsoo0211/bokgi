# 복기 프로토타입

먼저 판단하고, 결과를 되짚어 금융 개념을 배우는 투자 학습 앱 — 듀오링고 같은 학습 구조(짧은 일일 세션·간격 복습·연습 스트릭)를 쓰되, 적중률 게임은 넣지 않는다.

빌드 없는 정적 웹 프로토타입이다. 화면 흐름·판단 게이트·로그 구조를 손으로 확인하는 용도이며, 수치와 「그때」 소식은 예시 데이터다.

## 실행

- **VS Code Live Server**: `prototype/app/index.html`을 열고 *Open with Live Server*.
- **파일로 바로 열기**: 브라우저에서 `file:///…/prototype/app/index.html`. 모듈·번들러 없이 `<script>` 네 개(data → state → swipe → app)라 file://에서 그대로 돈다.
- **380px로 보기**: 개발자 도구 기기 모드에서 380×760. 화면 틀은 최대 380px이다.
- **처음 상태로**: 일지 → *세션 초기화*(판단·로그·복습 기록과 첫 실행 안내 표시 여부를 지운다). 또는 localStorage의 `bokgi.proto.v1`, `bokgi.onboarded`를 지운다.

## 화면 흐름

```
첫 실행  안내 3장 ① 주가 맞히기 게임이 아니에요 ② 하루 3장, 5분 ③ 결과와 회사 이름은 판단한 뒤에만 → [시작]

오늘     카드 ×3 → 복습 문제(복습일이 된 개념, 하루 2개까지) → 오늘은 여기까지 → '한 장 더'(허용, 기록)
         카드 한 장:
           판 「흐름」 「숫자」(기본) 「그때」
           → 이 회사를 아는 것 같아요(선택) → 핵심 근거(필수) → 위험 요인(선택) → 확신도 1~5(필수, 기본값 없음)
           → 스와이프 / 버튼 / 키보드 ← →  :  시장보다 뒤졌다 · 시장보다 앞섰다
           → 되돌리기 2.5초 (또는 [바로 공개])
           → 공개: 회사·기간·수익률(부호+모양+색), 앞섬/뒤짐/비슷, 내 판단, 사후에 중요했던 것,
                   AI 해설, 개념·확인 문제, [정보가 이상해요]

일지     판단 기록(최신순) → 통계(접힘, 20장 뒤에 열림) → 연구 로그 내보내기 · 세션 초기화
개념     개념 목록(숙련도·복습 예정) → 설명·확인 문제
```

- **머리줄** `오늘 n/3 · 스트릭 k일`. 스트릭은 판단을 1장 이상 남긴 날이 연속된 수(기기 현지 날짜)이고, 오늘 아직 안 했으면 어제까지로 센다. 정답과 무관하다.
- **카드 순서**: 덱 순서대로, 이미 판단한 사례는 건너뛴다. 덱이 바닥나면 "준비된 카드를 모두 봤어요".
- **결과 상태**: 시장 대비 |x| ≤ 1.0%p면 *비슷*(적중·실패로 세지 않음, `hit = null`), 그 밖은 *앞섬*/*뒤짐*이고 판단 방향과 같을 때만 `hit = true`.
- **간격 복습**: 확인 문제를 풀 때마다(공개·복습·개념 화면 모두) 다음 복습일을 정한다. level 0·1·2·3 → 1·3·7·21일. 맞히면 level +1(새 개념은 0부터), 틀리면 0. 복습일이 아직 안 된 개념을 다시 맞히면 그대로 둔다(같은 날 반복으로 간격이 부풀지 않게). 복습일은 그날 0시부터 유효하다.
- **되돌리기 창 중 이탈**: 다른 탭으로 가면 자동 공개를 멈추고(일지에는 "결과 대기"), 오늘 탭으로 돌아오면 바로 공개한다.

## 규칙 (리뷰에서 grep으로 확인)

1. 판단 전에 도는 코드는 `IFSAVE.OUTCOMES`를 읽지 않고 `--up`/`--down` 변수와 `ds-up`/`ds-down` 클래스를 쓰지 않는다. 공개 화면(`showReveal`)만 쓴다. 다른 화면(일지 등)은 공개 때 판단 기록에 붙여 둔 `j.result`만 읽는다.
2. 게이트: 핵심 근거와 확신도를 **둘 다** 고르기 전에는 스와이프·버튼·키보드가 모두 막힌다. 확신도 기본값은 없다.
3. 버튼과 키보드(← →) 대안이 항상 있다.
4. 적중률을 큰 숫자로 보이지 않는다. 랭킹 없음. 스트릭은 연습한 날 기준(정답 무관). 통계는 횟수와 글로만.
5. 「그때」 문장에는 회사 이름·티커·제품 이름·절대 날짜를 쓰지 않는다. 날짜는 `판단일 D-n`만, 판단일 이후 일은 넣지 않는다.

```sh
cd prototype
for f in app/js/*.js; do node --check "$f"; done
grep -n "OUTCOMES" app/js/app.js                      # showReveal 안 한 줄
grep -nE "ds-(up|down)|--up|--down" app/js/app.js     # showReveal 안에서만
grep -nE "ds-(up|down)|--up|--down" app/css/app.css   # 없음
```

## 저장과 로그

- `bokgi.proto.v1` = `{ judgments, events, concept_progress, review, quiz_log, reports, session }`
- `bokgi.onboarded` = `'1'`이면 첫 실행 안내를 건너뛴다.
- 판단 기록: `case_id, case_version, direction, key_evidence, risk_factor, confidence, recognized, extra, gesture{dx,ms,v,flips,via}, created_at`, 공개 뒤 `result{relative_pp, state, hit, return_pct, bench_return_pct, bench, company, ticker, period}`
- 복습: `review[conceptId] = { level, due_at, last_at, last_correct }`
- 신고: `reports[] = { id, created_at, case_id, case_version, category, note }`
- 이벤트: `onboarding_done, card_view, panel_view, recognize_toggle, evidence_pick, risk_pick, confidence_pick, gate_blocked, judge, undo, reveal_now, reveal, quiz, report_open, report, review_view, extra_card, concept_view, stats_toggle`

### 2026-10-03 — IfSave 학습지 프로토타입 → 복기 MVP 흐름

1. **제목·탭**: '복기 — 프로토타입', 아래 탭을 오늘·일지·개념으로, 역추적·리포트 탭 제거 — 역추적은 2단계로 미루고(D12) 리포트는 일지 안 통계로 옮겼다(D9).
2. **렌즈 → 판**: 차트/재무/복합 렌즈를 없애고 카드 안에 「흐름」「숫자」「그때」, 기본은 숫자, 전환마다 `panel_view` 기록 — 렌즈를 고르게 하면 '판단 스타일 비교'에 자기선택 편향이 생긴다(D8). 실제로 본 판은 로그로 남긴다.
3. **사례 `context`**: 금리·추세·판단일 전 소식 3개를 추가하고 `RETRO`는 "2단계 역추적용, MVP 미사용" 주석으로 남김 — 당시 시장 상황을 함께 보여 달라는 요구를 받되, 회사와 날짜가 새지 않게 상대 날짜로만 쓴다.
4. **게이트**: '이 회사를 아는 것 같아요' 체크, 확신도 기본값 제거, 버튼 '← 시장보다 뒤졌다' / '시장보다 앞섰다 →' — 아는 판단을 일지에서 구분하고, 기본값 3이 확신도를 끌어당기지 않게 하고, 방향을 '잘했다·못했다'가 아닌 시장 대비로 읽게 한다.
5. **되돌리기 알림의 [바로 공개]** — 2.5초를 기다리지 않아도 되게. 알림은 화면 아래에 고정해 스와이프로 판단해도 보인다.
6. **공개 화면**: 앞섬/뒤짐/비슷(±1%p) 세 상태와 비슷 = 적중·실패 제외, 숫자에 부호와 모양(▲▼■), '사후에 중요했던 것' 행, 신고 시트(8유형 + 메모 → `State.report`) — 작은 차이를 맞힘·틀림으로 세지 않고, 색만으로 읽히지 않게 하고, 카드 품질 문제를 그 자리에서 받는다.
7. **간격 복습** 1·3·7·21일(`S.review`) — 듀오링고식 구조 중 간격 복습을 들인다(D5).
8. **오늘 세션**: 카드 3장 + 복습 2개까지, `오늘 n/3 · 스트릭 k일`, 오늘은 여기까지 + 한 장 더(`extra_card`), 덱이 바닥나면 안내 — 짧은 일일 세션과 정답과 무관한 연습 스트릭만 들인다.
9. **일지**: 최신순 판단 기록(공개 전에는 업종·규모, 공개 뒤 회사·티커), '알고 판단' 표시, 접힌 통계는 20장 뒤에 근거별 횟수와 확신도 보정 한 줄(글)만, 로그 내보내기·초기화 이동 — 리포트 잠금이 베타 규모에서 영영 열리지 않던 모순을 풀고(D9) 적중률이 점수처럼 보이지 않게 한다.
10. **개념 화면**: 전체 개념의 숙련도·복습 예정, 탭하면 설명과 확인 문제(풀면 복습 일정) — 공개 화면 밖에서도 개념을 훑고 다시 풀 곳이 필요하다.

#### 같이 고친 것 (위 변경 중 드러난 문제)

- 카드 안 판 탭에서는 드래그를 시작하지 않게 함 — 카드의 포인터 캡처가 탭 클릭을 가로채지 않게(swipe.js는 그대로).
- 카드가 날아가는 220ms와 되돌리기 창 동안 게이트를 잠금 — 전에는 이 사이 버튼·키보드로 다음 카드까지 같은 근거로 판단될 수 있었다.
- 스와이프 도장 글자(잘했다/못했다)를 CSS로 '앞섰다/뒤졌다'로 — swipe.js를 고치지 않고 용어를 맞춘다.
- 숫자 판이 카드 안에서 잘리던 문제 — 메타를 한 줄 글로, 카드 안 행 간격을 줄이고 카드를 452px로(카드 3장 × 판 3개 모두 내부 스크롤 없이 들어감을 측정).
- 되돌리기 알림 버튼이 판단 전 화면에서 `--down`(파랑)을 쓰던 것을 잉크로.
- 해설을 기다리는 사이(또는 되돌리기 창 중) 다른 탭으로 가면 오류가 나거나 공개 화면이 다른 화면을 덮던 문제(화면 토큰), 퀴즈가 해설이 도착하기 전 눌리지 않던 문제.
- 틀린 답에 정답을 표시하고, 개념과 무관하던 고정 피드백('시장 대비를 기준으로…')을 정답·다음 복습일 안내로.
- 아래 탭 고정(sticky), 본문 여백 때문에 생기던 32px 빈 스크롤 제거, 한국어 어절 단위 줄바꿈.
- 위험 요인 칩은 다시 누르면 풀림(선택 항목이므로).
