# 복기 프로토타입

먼저 판단하고, 결과를 되짚어 금융 개념을 배우는 투자 학습 앱 — 듀오링고 같은 학습 구조(짧은 일일 세션·간격 복습·연습 스트릭)를 쓰되, 적중률 게임은 넣지 않는다.

빌드 없는 정적 웹 프로토타입이다. 화면 흐름·판단 게이트·로그 구조를 손으로 확인하는 용도이며, 수치와 「그때」 소식은 예시 데이터다.

## 실행

- **VS Code Live Server**: `prototype/app/index.html`을 열고 *Open with Live Server*.
- **파일로 바로 열기**: 브라우저에서 `file:///…/prototype/app/index.html`. 모듈·번들러 없이 `<script>` 네 개(data → state → swipe → app)라 file://에서 그대로 돈다.
- **380px로 보기**: 개발자 도구 기기 모드에서 380×760. 화면 틀은 최대 380px이다.
- **처음 상태로**: 일지 → *세션 초기화*(판단·로그·복습 기록과 첫 실행 안내 표시 여부를 지운다). 또는 localStorage의 `bokgi.proto.v1`, `bokgi.onboarded`를 지운다.

## 화면 흐름

```
첫 실행  안내 3장 ① 주가 맞히기 게임이 아니에요 ② 하루 3장, 5분 ③ 결과와 회사 이름은 판단한 뒤에만 → [시작]

오늘     [입장 카드] 개념 이해 n/전체 · 복습 예정 m개 / 오늘 남은 카드 k장 · (오른쪽) 스트릭 k일
         카드 ×3 → 복습 문제(복습일이 된 개념, 하루 2개까지) → 오늘은 여기까지 → '한 장 더'(허용, 기록)
         카드 한 장:
           판 「흐름」 「숫자」(기본) 「그때」
           → 이 회사를 아는 것 같아요(선택) → 핵심 근거(필수) → 위험 요인(선택) → 확신도 1~5(필수, 기본값 없음)
           → 스와이프 / 버튼 / 키보드 ← →  :  시장보다 뒤졌다 · 시장보다 앞섰다
           → 되돌리기 2.5초 (또는 [바로 공개])
           → 공개: 회사·기간·수익률(부호+모양+색), 앞섬/뒤짐/비슷, 내 판단, 사후에 중요했던 것(형광펜),
                   ○△✕ "내 근거는 이 개념과 맞았나요?"(난이도 2부터),
                   해설 세 줄(이번에 잘 읽은 것 · 다음에 바꿀 것 · 개념 연결), 개념(형광펜)·확인 문제, [정보가 이상해요]

일지     연습 달력(‹ 달 ›) → 판단 기록(최신순, ○△✕ 표시) → 통계(접힘, 20장 뒤에 인사이트 카드) → 연구 로그 내보내기 · 세션 초기화
개념     개념 목록(숙련도·복습 예정) → 설명·확인 문제
```

- **머리줄** `오늘 n/3`(한 장 더를 보면 `+n`). 스트릭은 머리줄에서 입장 카드 오른쪽으로 옮겨 한 번만 보인다.
- **입장 카드**(카드·복습·마침 화면 맨 위, 누르는 곳이 아님 — 카드는 바로 아래 있다): 1줄이 학습 — `개념 이해 n/전체`(상태가 '이해'인 개념 수 / 개념 수, 프로토타입은 4개) `· 복습 예정 m개`(오늘 세션에서 풀 복습 문제 수, 하루 2개 한도 반영). 2줄이 `오늘 남은 카드 k장`, 3장을 마치면 `오늘 끝 · 한 장 더 가능`(덱이 남았을 때) / `오늘 끝`(덱이 바닥) / `오늘 끝 · 한 장 더 보는 중`(한 장 더 카드), 덱이 비면 `남은 카드 없음`. 다음 카드의 개념(학습 포인트)은 결과를 암시하므로 넣지 않는다.
- **스트릭**(입장 카드 오른쪽, 12px, 강조 없음)은 판단을 1장 이상 남긴 날이 연속된 수(기기 현지 날짜)이고, 오늘 아직 안 했으면 어제까지로 센다. 정답과 무관하다.
- **연습 달력**(일지 맨 위, 월요일 시작 `월화수목금토일`): 판단한 날 = 잉크 점, 복습 예정일 = 테두리 원(기한이 지난 복습은 오늘로 당겨 센다), 오늘 = 빨간 펜 링. 아래 `이달 연습 n일 · 복습 n개`(다른 달은 `9월 연습 …`). `‹ ›`는 첫 판단이 있는 달 ~ 마지막 복습 예정일이 있는 달까지. **결과 상태로 칠하지 않는다**(연습 기록이지 적중 지도가 아니다). 결과가 나기 전(되돌리기 창 중)의 판단도 연습한 날로 센다.
- **○△✕ 자기 평가**: 공개 화면 '사후에 중요했던 것' 바로 아래 "내 근거는 이 개념과 맞았나요?" `○ 맞았다 · △ 일부 · ✕ 달랐다`(원칙 준수가 아니라 개념 확인). 고르면 빨간 펜 링, 다시 고를 수 있다. 판단 기록에 `self_check`로 남고 일지 행에 작은 표시(○/△/✕, `aria-label="개념 확인: …"`)로만 보인다. 점수·비율·집계로 만들지 않는다. 난이도 1 카드에서는 묻지 않는다(docs/06 §9 '난이도 2부터').
- **해설 세 줄**: `이번에 잘 읽은 것`(📄 출처 — 고른 근거와 공개된 숫자만 되풀이) → `다음에 바꿀 것`(🔍 추론 + 바로 옆 면책 한 줄) → `개념 연결`(📄 출처 — 카드의 학습 포인트 이름, 형광펜). 각 한 문장, 개념 줄이 늘 마지막이고 가장 진하다. 숫자 가드: 문장 속 숫자는 공개 화면에 나온 숫자와 고른 근거의 숫자만(어기면 숫자 없는 문장으로 바꾼다). 결과를 한 원인으로 단정하지 않는다.
- **인사이트 카드**(통계, 20장 뒤): 한 카드에 한 문장, 횟수만 — ① 가장 자주 고른 확신도에서 시장보다 앞선 횟수 ② 뒤짐이 가장 많은 근거 종류 ③ 아는 회사 / 모르는 회사의 앞섬 횟수. 같은 조건이 3번 미만이면 그 카드는 뺀다. 근거는 칩 글자가 아니라 **종류**로 묶는다(`PER 38 vs 27` → `PER`): 칩 글자는 카드마다 다르고 사례는 한 번만 판단하므로 글자 그대로는 3번이 쌓이지 않는다(덕분에 카드에 `%`도 나오지 않는다). 확신도 보정 한 줄은 그대로.
- **형광펜**(`--hl`, `.ds-hl`): 공개 화면의 '사후에 중요했던 것' 값, 해설의 개념 이름, 개념 카드 제목에만. 판단 전 화면·일지·개념 탭에는 없다.
- **카드 순서**: 덱 순서대로, 이미 판단한 사례는 건너뛴다. 덱이 바닥나면 "준비된 카드를 모두 봤어요".
- **결과 상태**: 시장 대비 |x| ≤ 1.0%p면 *비슷*(적중·실패로 세지 않음, `hit = null`), 그 밖은 *앞섬*/*뒤짐*이고 판단 방향과 같을 때만 `hit = true`.
- **간격 복습**: 확인 문제를 풀 때마다(공개·복습·개념 화면 모두) 다음 복습일을 정한다. level 0·1·2·3 → 1·3·7·21일. 맞히면 level +1(새 개념은 0부터), 틀리면 0. 복습일이 아직 안 된 개념을 다시 맞히면 그대로 둔다(같은 날 반복으로 간격이 부풀지 않게). 복습일은 그날 0시부터 유효하다.
- **되돌리기 창 중 이탈**: 다른 탭으로 가면 자동 공개를 멈추고(일지에는 "결과 대기"), 오늘 탭으로 돌아오면 바로 공개한다.

## 규칙 (리뷰에서 grep으로 확인)

1. 판단 전에 도는 코드는 `IFSAVE.OUTCOMES`를 읽지 않고 `--up`/`--down` 변수와 `ds-up`/`ds-down` 클래스를 쓰지 않는다. 공개 화면(`showReveal`)만 쓴다. 다른 화면(일지 등)은 공개 때 판단 기록에 붙여 둔 `j.result`만 읽는다.
2. 게이트: 핵심 근거와 확신도를 **둘 다** 고르기 전에는 스와이프·버튼·키보드가 모두 막힌다. 확신도 기본값은 없다.
3. 버튼과 키보드(← →) 대안이 항상 있다.
4. 적중률을 큰 숫자로 보이지 않는다. 랭킹 없음. 스트릭은 연습한 날 기준(정답 무관). 통계는 횟수와 글로만(인사이트 카드에 `%` 없음). ○△✕ 자기 평가는 합산하지 않는다.
5. 「그때」 문장에는 회사 이름·티커·제품 이름·절대 날짜를 쓰지 않는다. 날짜는 `판단일 D-n`만, 판단일 이후 일은 넣지 않는다.
6. 형광펜 `.ds-hl`(`--hl`)은 공개 화면(`showReveal`)에서만. 연습 달력·입장 카드는 결과 상태(앞섬·뒤짐·비슷)로 칠하지 않고, 입장 카드에 다음 카드의 개념을 넣지 않는다.

```sh
cd prototype
for f in app/js/*.js; do node --check "$f"; done
grep -n "OUTCOMES" app/js/app.js                      # showReveal 안 한 줄
grep -nE "ds-(up|down)|--up|--down" app/js/app.js     # showReveal 안에서만
grep -nE "ds-(up|down)|--up|--down" app/css/app.css   # 없음
grep -n "ds-hl" app/js/app.js                         # showReveal 안에서만 (사후 값 · 개념 카드 제목 · 해설 개념 이름)
node tests/smoke.cjs                                  # 모두 PASS, console errors/warnings: none
```

## CHANGELOG

### 2차 변경 (2026-10-03) — 레퍼런스 SLAP·Hedge에서 여섯 가지 (docs/06 §9)

복기의 정체성은 **투자 판단 학습**이다. 레퍼런스에서는 구조만 빌리고 모양·지표는 학습지와 개념 쪽으로 바꿨다.

1. **입장 카드**(SLAP의 "평가 안 한 소비 n건" 입장 카드) — 오늘 맨 위 `.ds-entry`: 1줄 `개념 이해 n/전체 · 복습 예정 m개`, 2줄 `오늘 남은 카드 k장`(3장 뒤 `오늘 끝 · 한 장 더 가능`), 오른쪽 `스트릭 k일`(caption). 해야 할 일보다 학습을 앞에 두고, 버튼이 아니라 카드는 탭 없이 바로 아래, 다음 카드의 개념은 결과 암시라 넣지 않는다. 스트릭은 머리줄에서 옮겨 한 번만 보인다.
2. **연습 달력**(SLAP의 만족·후회 색 점 달력) — 일지 맨 위, 판단한 날 잉크 점·복습 예정일 테두리 원·오늘 빨간 펜 링, `이달 연습 n일 · 복습 n개`, `‹ ›`. 색 점(결과)을 버리고 괘선 표 위의 작은 표시로 — 적중 지도가 아니라 연습 기록이다.
3. **○△✕ 자기 평가**(Hedge의 원칙별 지켰어요/보통/안 지켰어요) — 공개 화면 '사후에 중요했던 것' 바로 아래 "내 근거는 이 개념과 맞았나요?", `State.selfCheck`, `self_check` 기록·로그, 일지 행에 작은 표시(`aria-label="개념 확인: …"`). 원칙 준수 점검이 아니라 개념 확인이고, Hedge의 ○4 △1 ✕0 집계·배지는 두지 않는다. 난이도 2 카드부터.
4. **해설 세 줄**(Hedge의 "앞으로도 유지 / 고쳐보면 좋아요" 두 묶음) — `AI.explain`을 `이번에 잘 읽은 것`(📄) · `다음에 바꿀 것`(🔍 + 면책) · `개념 연결`(📄) 세 줄로, 줄마다 머리글과 라벨. 개념 줄을 늘 마지막에 가장 진하게(개념 이름에 형광펜) 두어 해설이 개념 학습으로 끝나게 했다. 숫자 가드를 스텁에도 넣었다.
5. **인사이트 카드**(SLAP의 "패턴 발견" 한 줄 카드) — 20장 뒤 통계의 근거별 횟수 행을 한 문장 카드 1~3장(확신도·근거 종류·아는 회사)으로 바꿨다. 퍼센트·적중률·순위·전월 대비는 쓰지 않고 횟수만, 같은 조건 3번 미만이면 뺀다. 잠금 문구는 그대로.
6. **형광펜 밑줄 토큰**(SLAP의 제목 위 초록 형광펜) — `--hl: #d9f5c7`(tokens.json `hl`: "학습지 형광펜 — 공개 뒤 화면 전용"), `.ds-hl`. 제목 장식이 아니라 공개 화면의 개념 이름 세 곳(사후에 중요했던 것 값·해설 개념 연결·개념 카드 제목)에만 — 판단 전 강조 한 곳 원칙과 겹치지 않게.

#### 같이 고친 것

- 조사 고르기(`State.josa`): `'가이던스 상향'를`처럼 받침과 어긋나던 해설 문장을 `을/를 · 이/가 · 과/와 · 이에요/예요`로 맞췄다(숫자·영문은 읽는 소리 기준).

- 스모크 테스트 102개 → 144개: 입장 카드 문구·위치·개념 누설 없음, 달력(오늘 링·연습 점·복습 원·캡션·결과 클래스 없음·달 넘기기), 자기 평가 저장·로그·일지 표시·난이도 1 제외, 해설 세 줄·면책 위치·한 문장·숫자 가드, `.ds-hl` 공개 전 0개·공개 뒤 3곳, 인사이트 문장·`%` 없음·건너뛰기 규칙, 조사.

#### 알려진 한계

- `개념 이해 n/전체`의 분모는 데이터의 개념 수다. 프로토타입은 4개라 `0/4`로 보이고, 개념 20개(MVP)가 들어오면 `n/20`이 된다.
- 예시 사례 3장으로는 같은 조건 3번이 쌓이지 않아, 인사이트 카드와 달력 넘기기는 스모크 테스트의 주입 데이터로만 확인했다.
