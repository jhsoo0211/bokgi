# 복기 디자인 시스템 — 학습지(Worksheet)

_워크시트 디자인 시스템(2026-09-30)을 이관하고 복기 결정에 맞게 고쳤다. 토큰·컴포넌트 파일은 `prototype/design/`에 있다(`tokens.json` 원본, `tokens.css`, `components.css`)._

먼저 판단하고, 결과를 되짚어 배우는 학습 서비스. 흰 종이에 굵은 제목, 괘선과 각진 답란, 선택은 빨간 펜 동그라미, 결과는 도장. 장식은 없다.

## 1. 원칙

1. **판단 전에는 결과색이 없다.** `up`·`down`은 공개 화면에서 처음 나타난다. 판단 전 화면의 유일한 강조는 `action` 하나.
2. **상승은 빨강, 하락은 파랑**(국내 관행). 색만으로 구분하지 않고 **부호(+/−)와 도형(▲ ▼ ■)**을 함께 쓴다.
3. **근거는 문장 옆에 붙는다.** AI 문장은 📄 출처 / 🔍 추론 / ❓ 불확실 라벨을 문장 단위로. 하단 면책 한 줄로 대신하지 않는다.
4. **정답 맞히기가 아니라 근거 남기기.** 적중률 히어로 숫자, 랭킹, 연승 배지는 만들지 않는다. 스트릭은 작은 글씨로 '연습한 날'만.
5. **한 화면에 강조 한 곳.** `action`은 화면당 한 요소에만.
6. **흐린 그림자는 없다.** 그림자는 단색 오프셋뿐.

## 2. 색

| 역할 | 토큰 | 규칙 |
|---|---|---|
| 바탕 3단 | `bg-000` `bg-100` `bg-200` | 화면 → 카드 → 눌림/뒤 카드 |
| 글자 3단 | `ink-900` `ink-500` `ink-200` | 본문 → 보조 → 괘선·테두리 |
| 판단 강조 | `action` `action-ink` | 주 판단 버튼, 진행 바 |
| 선택 | `select` `select-ink` | 선택된 칩: 빨간 펜 링. 선택된 판 탭: 잉크로 채움 |
| 시장 결과 | `up` `down` | **공개 화면 전용**. 비슷함은 `ink-900` 테두리 도장 |
| 근거 라벨 | `label-source` `label-inference` `label-uncertain` | 테두리·글자만 |
| 포커스 | `focus` | 2px 링, 3:1 이상 |

대비: `ink-900`/`bg-000` 15.9:1, `ink-500`/`bg-000` 5.2:1, `up` 5.0:1, `down` 6.0:1.

## 3. 글자

Pretendard 하나(400·500·600·700). 제목 700(자간 −1%), 본문 400(줄간격 22px), 숫자 700에 `tnum`. 스케일 `.b-display`(26/32) `.b-title`(18/24) `.b-body`(14/22) `.b-caption`(12/18) `.b-num`(15/20). 본문 줄 길이 40자 이내. 음수 부호 U+2212.

## 4. 간격·반경·테두리

간격 6단 4~32px. 카드 안쪽 12/16, 카드 사이 12, 섹션 사이 24. 답란·칩·버튼은 각진 모서리(`--radius-0`), 라벨·진행 바·도장은 pill. 답란·괘선 1.5px, 포커스 링과 펜 링 2px. 그림자 없음.

## 6. 상호작용 — 스와이프 카드(SwipeCard 규칙)

```
온보딩(첫 1회) → 오늘 카드 → 판 보기(흐름·숫자·그때) → 아는 회사 체크(선택) → 근거 칩 1개(필수) → 확신도(필수)
→ 좌우 스와이프 또는 버튼 → 되돌리기 2.5초(또는 '바로 공개') → 공개 → 개념·문제 → 다음 카드 → 오늘 끝
```

- 스택 3장(현재 + 뒤 2장 peek). 뒤 카드는 터치를 받지 않는다.
- 오른쪽 = 시장보다 앞섰다, 왼쪽 = 뒤졌다. 위·아래 스와이프는 기능이 없다.
- 이탈 임계 `max(80px, 너비×0.30)` 또는 속도 0.6px/ms. 회전 ±12°.
- **게이트:** 근거와 확신도를 모두 고르기 전에는 임계를 넘어도 되돌아온다. 칩 영역이 흔들리고 힌트가 바뀐다.
- **되돌리기:** 이탈 뒤 2.5초 토스트. '바로 공개'로 건너뛸 수 있다. 되돌리면 기록을 지우고 같은 카드로 돌아온다(되돌림 이벤트는 남긴다).
- **대체 입력:** 버튼 2개와 키보드 ←→는 항상 있다. `prefers-reduced-motion`이면 이탈 애니메이션 없이 즉시 전환.
- **기록:** 방향, 근거, 거리, 시간, 속도, 방향 전환 횟수. 스와이프 거리로 확신도를 추정하지 않는다.
- 공개는 카드가 이탈한 뒤 별도 화면으로 온다. 판단 전 카드 뒷면에 결과를 두지 않는다.

## 7. 화면 패턴

- **오늘:** 상단 `오늘 n/3 · 스트릭 k일`(caption), 진행 바, 스택, 판 탭, 게이트, 버튼, 힌트.
- **공개:** 회사·기간(title) → 결과 상태 한 줄 + 도장 → 수치 3칸 → 경로 → 내 판단 표 → 사후에 중요했던 것 → 해설(라벨) → 개념 + 문제 → 신고 → 다음.
- **일지:** 행 목록(날짜·회사 또는 업종·방향·근거·확신도·상태·'알고 판단'), 접힌 통계(20장 뒤), 내보내기·초기화.
- **개념:** 네 갈래 머리글 아래 20개, 상태 뱃지(테두리만), 복습 예정일.

## 8. 쓰는 법

1. `tokens.css` → `components.css` → 화면 CSS 순으로 불러온다.
2. `<html data-theme="worksheet">`.
3. 컴포넌트는 의미 색 토큰과 `--ds-*`만 쓴다.
4. 판단 전 화면에서 `--up` `--down`·`ds-up` `ds-down`을 쓰는 코드는 리뷰에서 막는다(grep 검사).

## 9. 참고 레퍼런스 (2026-10-03, 사용자 제안)

| 레퍼런스 | 무엇을 가져오나 | 무엇을 가져오지 않나 |
|---|---|---|
| **SLAP — 스와이프로 끝내는 가계부** (Behance, https://www.behance.net/gallery/241848891/SLAP-) | 스와이프 한 번으로 분류를 끝내는 리듬. 복기에서는 **오른쪽 = 시장보다 앞섰다, 왼쪽 = 뒤졌다**로 방향이 곧 판단이다. 카드가 날아가며 남는 짧은 확인 피드백 | 가계부의 금액 입력·카테고리 색상 체계. 결과색은 공개 전에 쓰지 않는다는 원칙이 우선 |
| **채점지(답안지) 형태** | 괘선 위에 답을 적고 빨간 펜으로 ○·× 채점을 받는 모양. 공개 화면의 '내 판단' 표를 답안 행으로, 결과 상태를 채점 도장(앞섬·뒤짐·비슷함)으로. 일지는 채점이 끝난 답안지 묶음 | '점수 합계'란. 적중률 합산 칸은 두지 않는다(ADR-0002) |

**SLAP에서 본 것(표지 모듈 기준).** 흑백 바탕에 초록·파랑 두 가지 강조색. 홈 화면은 ① 월 달력 — 날마다 동그라미가 초록(만족)·파랑(후회)으로 칠해지고 몇 개는 웃는·우는 얼굴, 위에 "만족 36건 · 후회 27건" ② "평가 안 한 소비 8건 → 평가하러 가기" 입장 카드(검은 주 버튼) ③ "남은 예산 390,840원" 진행 바(72.8%) ④ 하단 탭 홈·가계부·분석·설정. 즉 **스와이프 한 번의 결과가 달력의 점으로 쌓이고, 아직 안 한 일이 입장 카드로 보이는 구조**다.

**복기로 옮기는 방식**

| SLAP 요소 | 복기 대응 | 주의 |
|---|---|---|
| 월 달력의 색 점 | **일지 상단의 연습 달력**: 연습한 날 = 잉크 점, 복습 예정일 = 테두리 원, 오늘 = 펜 링 | 점의 색을 **결과 상태(앞섬/뒤짐)로 칠하지 않는다**. 달력이 적중 지도가 되면 ADR-0002를 어긴다. 상태는 답안 행의 도장에만 |
| 만족 n건 · 후회 n건 | "이달 판단 n장 · 복습 n개" | 적중 수를 세지 않는다 |
| 평가 안 한 소비 → 평가하러 가기 | 오늘 화면 맨 위 입장 카드 "오늘 남은 카드 2장 → 판단하러 가기", 복습 기한이 있으면 "복습 1개" | 주 버튼은 화면당 하나(원칙 5) |
| 남은 예산 진행 바 | 오늘 진행 바(n/3) 그대로 | 월 단위 목표 수치는 두지 않는다 |
| 스와이프로 만족/후회 분류 | 스와이프로 앞섬/뒤짐 판단(방향 = 판단) | 게이트(근거 + 확신도) 뒤에만 열린다 |
| 두 강조색 | 결과색 빨강·파랑은 공개 뒤에만. 판단 전 강조는 `action` 하나 | — |

**SLAP 전체 모듈(23장)에서 더 본 것.** ① 문제 정의는 "쓰고는 있는데 쓰는 줄은 아시나요", "소비는 이성보다 감정에 먼저 반응"으로 시작하고 인터뷰 네 장면("같은 지출이라도 상황에 따라 의미가 달라져요", "기록해도 성과가 보이지 않았어요", "분류·입력이 노동처럼")으로 잇는다. ② 핵심 동작은 소비 한 건을 카드로 보여 주고 스와이프로 만족/후회를 고르는 것. ③ 분석 화면은 '이번 달 후회 43%(전월 대비)', 후회 많은 카테고리 순위, 요일·시간대 막대, 그리고 **"패턴 발견: 금요일 밤 10시 이후에 후회가 집중돼요"** 한 줄 인사이트 카드. ④ 사용성 테스트의 교훈: 스와이프 평가는 성공률 100%였지만 "개념은 통했지만 과정이 너무 길었다", 분석은 "인사이트는 최고점, 경로는 미로", 카드 추천은 "왜 이 카드인지 몰라요". ⑤ 시각: 흑백 바탕, 제목 위 초록 형광펜 하이라이트, 초록·파랑 두 색.

**Hedge — 주식 투자 회고 서비스** (Behance, https://www.behance.net/gallery/238904541/Hedge-, DEPROMEET 17th). 복기와 가장 가까운 이웃이다. 자기 **실제 매매**를 입력하고(매수/매도·금액·수량·날짜·수익률), 원칙 묶음(예: 초보자를 위한 매도 원칙)을 골라 원칙마다 **지켰어요 / 보통이에요 / 안 지켰어요** 세 단계로 체크하며 화면을 옆으로 넘기고, 매매 근거를 적고 사진·링크를 붙인다. 결과는 배지("최고의 매매")와 ○4 △1 ✕0 집계, AI 분석을 **"앞으로도 유지해보세요 / 고쳐보면 좋아요"** 두 묶음으로 준다. 조사 수치: 회고 경험 72%지만 효과를 느낀 사용자는 적음, 기회를 놓친 이유는 타이밍 계획 부재 41%·원칙 부재 35%·기준 부재 32%, 원칙을 못 지킨 이유는 감정 개입 48%·자기 검증 방법 부재 43%·개념 몰라서 30%. 시각은 짙은 남색 + 네온 초록 + 3D 배지로 학습지 방향과 반대다.

| Hedge 요소 | 복기 대응 | 주의 |
|---|---|---|
| 원칙별 ○△✕ 세 단계 체크 | 공개 화면의 '사후에 중요했던 것' 아래 **"내 근거는 이 개념과 맞았나" ○△✕ 자기 평가** 한 줄(난이도 2부터) | 점수로 합산하지 않는다. 일지에 기록만 |

두 레퍼런스 모두 '학습지' 방향(흰 종이·괘선·각진 답란·도장)과 충돌하지 않는다. 스와이프 리듬과 달력·입장 카드·인사이트 카드는 SLAP에서, ○△✕ 자기 평가와 해설자 두 묶음은 Hedge에서, 공개·일지의 모양은 채점지에서 가져온다.

**닮지 않기 위한 경계(2026-10-03, 사용자: "메인은 투자 학습, 기존 것들과 너무 같으면 안 된다").**
- 복기의 중심은 **판단 → 공개 → 개념 → 복습**의 학습 루프다. 레퍼런스에서 가져온 것은 전부 **표현 장치**(달력·입장 띠·인사이트 문장·두 묶음 피드백·○△✕ 한 줄)이고, 어느 것도 화면의 주인공이 아니다. 각 화면의 주인공은 카드(판단 전), 개념(공개 뒤), 기록(일지)이다.
- 가져오지 않는 것: SLAP의 **소비 평가와 카드(상품) 추천**, Hedge의 **실거래 입력과 원칙 체크리스트 중심 구조**, 두 서비스의 색·배지·3D 연출. 복기는 결과를 모르는 과거 사례로 **먼저** 판단하고 개념을 배우는 앱이며, 실거래·소비 기록을 받지 않는다.
- ○△✕는 '원칙을 지켰나'가 아니라 **"내 근거는 이 개념과 맞았나"**라는 개념 확인이다. 입장 띠는 '밀린 일'이 아니라 **개념 이해 n/20·복습 예정**을 앞세운다. 달력 점은 연습한 날이지 성과가 아니다.
- 차별 점검 두 가지: ① 모든 화면에 개념 또는 근거가 보이는가 ② 결과·점수·순위가 화면의 첫 번째 정보인 곳이 있는가(있으면 고친다).
