# ADR-0001 판단 전 자료와 판단 후 자료를 물리적으로 분리한다

- 상태: 채택 (2026-10-03)
- 관련: `CONTEXT.md`의 '결과', '공개', '누수'

## 맥락

복기의 가치는 "결과를 모른 채 판단한다"에서 나온다. 결과(회사 이름·날짜·수익률·가격 경로)가 판단 전에 조금이라도 비치면 — 화면에서든, AI 질문자의 말에서든, 네트워크 응답에서든 — 학습 루프 전체가 무너진다. 프로토타입은 한 파일에 판단 전·후 자료를 두고 "코드가 reveal 뒤에만 읽는다"는 규율에 의존했다. 규율은 깨지기 쉽다.

## 결정

1. 판단 전 자료(`cases`, `case_blocks`)와 판단 후 자료(`case_outcomes`)를 **다른 테이블**에 두고, 판단 전 API는 outcome 테이블을 조인하지 않는다.
2. 판단 전 API 응답은 **화이트리스트 스키마**로만 직렬화한다. 자동 테스트가 모든 판단 전 응답에서 회사명·티커·절대 날짜·수익률 필드가 0건임을 확인한다.
3. AI 질문자의 컨텍스트에는 판단 전 자료만 들어가고, 응답은 누수 필터를 통과해야 사용자에게 간다.
4. 판단 시점(`data_cutoff`)은 서버만 안다. 판단 전에는 상대 날짜만 쓴다.

## 대안

- 한 테이블에 두고 직렬화 때 필드를 빼는 방법 — 한 번의 실수로 전부 노출된다. 거절.
- 클라이언트에 결과를 암호화해 내려보내고 공개 때 복호화 — 키가 클라이언트에 있으면 의미가 없다. 거절.

## 결과

- 조회가 두 번(판단 전, 공개 때)으로 나뉜다. 공개 응답 지연은 수용한다.
- 카드 제작 도구도 판단 전·후 파일을 분리해 산출한다.
- 되돌리기는 공개 전에만 가능하다. 공개 뒤 되돌리기는 결과를 본 뒤의 수정이므로 금지.
