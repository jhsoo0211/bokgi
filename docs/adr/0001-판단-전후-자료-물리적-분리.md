# ADR-0001 판단 전 자료와 판단 후 자료를 물리적으로 분리한다

- 상태: 채택 (2026-10-03)
- 관련: `CONTEXT.md`의 '결과', '공개', '누수'

## 맥락

복기의 가치는 "결과를 모른 채 판단한다"에서 나온다. 결과(회사 이름·날짜·수익률·가격 경로)가 판단 전에 조금이라도 비치면 — 화면에서든, AI 질문자의 말에서든, 네트워크 응답에서든 — 학습 루프 전체가 무너진다. 프로토타입은 한 파일에 판단 전·후 자료를 두고 "코드가 reveal 뒤에만 읽는다"는 규율에 의존했다. 규율은 깨지기 쉽다.

## 결정

1. 자료를 **세 등급**으로 나눈다. ① 판단 전(`cases`, `case_blocks`) ② 공개 뒤(`case_outcomes`, `case_reveal`, 학습 포인트·연결 문장·원문 출처) ③ 서버 전용(누수 사전·제작 메모). ①의 어느 열과 jsonb에도 ②③ 값을 두지 않는다. 판단 시점의 절대 날짜도 ①에 없다(공개 쪽 `start_date`가 유일한 원본).
2. 판단 전 읽기 경로는 **하나**(`toPublicCase()`, 엄격한 스키마)이고 Route Handler·서버 컴포넌트·질문자가 모두 이것만 쓴다. ②③ 모듈은 서버 전용으로 격리하고 린트로 막는다.
3. 자동 시험은 필드명이 아니라 **카나리 값**(가짜 회사명·티커·날짜·수익률)을 판단 전 HTML·RSC·API·오류·AI 응답·일지의 결과 대기 행에서 찾아 0건을 확인한다.
4. AI 질문자의 컨텍스트에는 판단 전 자료만 들어가고, 응답은 누수 필터를 통과해야 사용자에게 간다. 누수 사전은 서버가 만들고 번들에 넣지 않는다.
5. 세션의 결과 균형 같은 규칙은 런타임이 아니라 제작 도구가 덱 순서로 굳힌다. 판단 전 경로는 결과를 읽지 않는다.

_2026-10-03 ecc 백엔드 검토(#1·#2·#3)로 1~3·5를 보강했다._

## 대안

- 한 테이블에 두고 직렬화 때 필드를 빼는 방법 — 한 번의 실수로 전부 노출된다. 거절.
- 클라이언트에 결과를 암호화해 내려보내고 공개 때 복호화 — 키가 클라이언트에 있으면 의미가 없다. 거절.

## 결과

- 조회가 두 번(판단 전, 공개 때)으로 나뉜다. 공개 응답 지연은 수용한다.
- 카드 제작 도구도 판단 전·후 파일을 분리해 산출한다.
- 되돌리기는 공개 전에만 가능하다. 공개 뒤 되돌리기는 결과를 본 뒤의 수정이므로 금지.
