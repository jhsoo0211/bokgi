# 복기 구현계획 v1.0

_기준: 기획안 v1.0 · 결정 D13(Next.js 풀스택 + Postgres, 맥미니 beta 슬롯) · 기간 2026-10-06 ~ 2027-01-02(13주)_

## 0. 구현 원칙

1. **판단 전 자료와 판단 후 자료를 물리적으로 분리한다.** 테이블·API·프롬프트 컨텍스트 모두. 판단 전 API 응답은 화이트리스트 스키마로만 나가고, 자동 테스트가 결과 필드 0건을 확인한다. (`adr/0001`)
2. **AI는 서버가 준 것만 말한다.** 숫자 발화 제한 → 누수 필터 → 라벨 부착.
3. **카드 1개 = 세 판.** 콘텍스트는 한 스키마에 저장하고 판은 렌더링 구획이다.
4. **모든 판단·세션 이벤트는 기록한다.** 카드 버전·열어 본 판·근거·확신도·AI 대화 유무·아는 회사 체크.
5. **적중률은 저장은 하되 집계 화면에 숫자로 내지 않는다.** (`adr/0002`)

## 1. 시스템 구성

```
브라우저(모바일 웹, Next.js App Router)
  오늘 · 공개 · 일지 · 개념 · 신고 · 온보딩
        │ Route Handlers (/api/*)
서버(Next.js 서버, 같은 컨테이너)
  cards(판단 전 조회) · judgments · reveal · concepts/review · sessions · reports · events
  ai: questioner · explainer · guards(numberGuard → leakFilter → labels) · budget
Postgres(컨테이너 bokgi-db)
  cases · case_blocks · case_outcomes(별도 접근 경로) · concepts · case_learning_points
  users · invites · sessions_auth · judgments · concept_progress · review_schedule
  daily_sessions · reports · card_versions · events
오프라인 제작 도구(tools/cards, Python·TS)
  공공 자료 수집 → 세 판 초안 → 마스킹 → 체크리스트 자동 검사 → 버전 부여 → seed
```

## 2. 스택·배포

- Next.js 16(App Router, Route Handlers), TypeScript, Prisma, Postgres 16. 테스트는 Vitest + Playwright(프론트 e2e는 IfSave 프론트의 설치본 재사용).
- compose 프로젝트 `bokgi`: `bokgi-web`(127.0.0.1:3100), `bokgi-db`(127.0.0.1:5433, 볼륨 `bokgi_pgdata`). beta 스택을 내린 뒤 올린다.
- 공개: Cloudflare 터널 ingress `bokgi.ifsave.com → http://127.0.0.1:3100`. HTTPS는 터널이 끝낸다.
- 환경변수(이름만): `DATABASE_URL`, `SESSION_SECRET`, `INVITE_CODES`(쉼표 구분, 베타용), `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`, `AI_FALLBACK_API_KEY`, `AI_FALLBACK_BASE_URL`, `AI_FALLBACK_MODEL`, `AI_DAILY_CALL_CAP`, `PUBLIC_ORIGIN`.
- 인증: 초대 코드 입력 → 닉네임 → 서명된 쿠키 세션(HttpOnly·Secure·SameSite=Lax). 비밀번호·이메일 없음. 코드는 1인 1회.
- 감시: 워치독 확인 URL 추가, UptimeRobot 모니터 1개. 배포 스크립트는 `.env` 검증 → `compose up -d --build` → `/api/health` 대기.

## 4. API

| 메서드 | 경로 | 반환 | 규칙 |
|---|---|---|---|
| GET | `/api/session/today` | 오늘 카드 3장의 id·진행, 기한 된 복습 ≤2, 스트릭 | 날짜는 사용자 로컬 기준(쿠키에 시간대) |
| GET | `/api/cases/{id}` | 메타 + 세 판 | **outcome 필드 없음**(화이트리스트 직렬화) |
| POST | `/api/judgments` | judgment_id | 서버가 근거·확신도 필수 검증. 판단 전 panels_viewed 저장 |
| POST | `/api/judgments/{id}/undo` | 200 | revealed_at 없을 때만, 생성 2.5초 이내 |
| POST | `/api/judgments/{id}/reveal` | outcome + state + 개념 + 문제 + 해설 | 이 시점에만 outcome 반환. 되돌리기 불가로 전환 |
| POST | `/api/concepts/{id}/quiz` | 채점, 다음 복습일 | review_schedule 갱신 |
| GET | `/api/journal` | 판단 목록, 통계(20장 미만이면 locked) | 적중률 숫자 필드 없음, 글 요약만 |
| GET | `/api/concepts` | 20개 + 상태 + 복습 예정 | |
| POST | `/api/ai/question` | 질문자 응답(라벨 포함) | 컨텍스트: 세 판 + 사용자 근거·확신도. 가드 통과 실패 시 템플릿 질문 |
| POST | `/api/ai/explain` | 해설자 응답(라벨 포함) | 공개 뒤에만 |
| POST | `/api/reports` | 접수 | 카드 버전 자동 첨부 |
| POST | `/api/events` | 200 | 배치 |
| POST | `/api/auth/invite` | 세션 쿠키 | 코드 1회 |

## 5. AI 오케스트레이터

| 역할 | 시점 | 컨텍스트에 넣는 것 | 절대 넣지 않는 것 |
|---|---|---|---|
| 질문자 | 공개 전 | 세 판(상대 날짜), 사용자 근거·확신도, 어조 | outcome, 회사명, 절대 날짜 |
| 해설자 | 공개 후 | outcome, 사용자 판단, 학습 포인트 개념 | 문서 밖 원인 단정 요구 |

- 질문자 템플릿 유형 6종(기획안 §8.1). 프롬프트는 유형을 하나 고르고 그 틀로만 두 문장을 쓰게 한다.
- 가드 체인: `numberGuard`(허용 숫자 집합 대조) → `leakFilter`(규칙: 기준일 이후 날짜 표현, 회사·티커·제품명 사전, outcome 수치; 판정 1회: "판단 시점 이후 정보를 담는가") → `labels`(문장 단위 📄/🔍/❓) → 어조 레이어.
- 실패·한도 초과 시 템플릿 질문(유형별 고정 문장 3개씩).
- 기록: 누수 필터 발동, 템플릿 폴백, 지연 시간을 events에.

## 6. 카드 제작 파이프라인 (tools/cards)

```
pick_case.py       # 후보(회사·판단 시점·기간) 목록, 결과 균형(앞섬/뒤짐/비슷함) 확인
numbers_from_filings.py  # 공시 원문 → 숫자 판 초안(공시일 ≤ 판단 시점 확인)
then_template.py   # 금리·거시(공개 통계) + 사람이 쓴 이슈 문장(상대 날짜·출처 종류) 조립
flow_index.py      # 판단 시점 100 기준 14점 파생 지수 + 시장 지수(연구 채택 자료는 계산 입력으로만)
outcome.py         # 결과 수익률(배당·분할 반영), 세 상태 계산, 가격 경로 14점
mask.py            # 이름·티커·제품명·절대 날짜 제거(연구 anonymization 재사용)
check_case.py      # 체크리스트 자동 검사: 판단 시점 이후 날짜 0건, 사전 매칭 0건, 공시일 ≤ 기준일, 출처 필수, 배당·분할 반영 플래그
seed.ts            # 통과한 카드만 status=live로 적재, 버전 부여
```

수작업: 사례 선정, 이슈 문장 작성, 학습 포인트 지정, 검토 승인. 목표: 8주차까지 30장(미국 24·국내 6).

## 7. 세션·복습 규칙

- 하루 = 사용자 로컬 날짜. 세션 카드 3장은 미판단 카드 중 난이도 오름차순·결과 균형(앞섬/뒤짐/비슷함이 연속 3장 같지 않게).
- 복습 기한: 맞히면 level+1(간격 1·3·7·21일), 틀리면 level 0(1일). 하루 2개 상한, 기한 지난 것부터.
- 스트릭: 세션 카드 1장 이상 판단한 날이 연속된 수. 끊겨도 비난 문구 없음.
- 통계(20장 뒤): 근거별 횟수, 확신도 구간별 결과 상태 분포(글), 아는 회사/모르는 회사 비교(글).

## 8. 테스트 계획

| 대상 | 방법 | 통과 기준 |
|---|---|---|
| 결과 유출 | 판단 전 API 응답 전부에 outcome·회사명·절대 날짜 필드 탐색 | 0건 |
| 누수 필터 | 결과를 유도하는 질문 100개 | 누설 0건, 오탐 < 10% |
| 방향 중립성 | 카드 30장 × 질문 3회의 질문 유형 분포 vs 결과 상태 | 유의한 상관 없음(기술적 보고) |
| 숫자 발화 제한 | 기존 IfSave 테스트셋 이식 | 동일 통과 |
| 마스킹 | 카드 30장 식별 점검(연구 도구) | 식별률은 기록만(가벼운 마스킹), **결과 유출 0건** |
| 세션 규칙 | 날짜 경계·시간대·복습 기한 단위 테스트 | 전부 통과 |
| 이벤트 | 누락률 | < 1% |
| e2e | 온보딩 → 카드 3장 → 공개 → 일지 → 개념 (380px) | 통과, 스크린샷 보존 |
