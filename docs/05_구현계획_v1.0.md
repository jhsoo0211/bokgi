# 복기 구현계획 v1.0

_기준: 기획안 v1.0 · 결정 D13(Next.js 풀스택 + Postgres, 맥미니 beta 슬롯) · 기간 2026-10-06 ~ 2027-01-02(13주)_

## 0. 구현 원칙

1. **자료를 세 등급으로 나눈다.** ① 판단 전 `cases`·`case_blocks` ② 공개 뒤 `case_outcomes`·`case_reveal`(회사·티커·날짜·수익률·경로·원문 출처·학습 포인트·사후에 중요했던 것) ③ 서버 전용(누수 사전·제작 메모). ①의 행과 jsonb에는 ②③ 값이 없다. 판단 전 읽기는 `toPublicCase()` 하나로 한다(Route Handler·서버 컴포넌트·질문자 공통, zod `.strict()`). ②③ 모듈은 `import "server-only"`와 린트로 격리하고, 오늘·카드·일지의 결과 대기 행·질문자는 `case_outcomes`를 읽지 않는다. 자동 시험은 필드명이 아니라 **카나리 값**(가짜 회사명·티커·날짜·수익률)을 원문에서 찾는다. (`adr/0001`, ecc 검토 #1·#3)
2. **AI는 서버가 준 것만 말한다.** 숫자 발화 제한 → 누수 필터 → 라벨 부착.
3. **카드 1개 = 세 판.** 콘텍스트는 한 스키마에 저장하고 판은 렌더링 구획이다.
4. **모든 판단·세션 이벤트는 기록한다.** 카드 버전·열어 본 판·근거·확신도·AI 대화 유무·아는 회사 체크.
5. **적중률은 저장은 하되 집계 화면에 숫자로 내지 않는다.** (`adr/0002`)

## 1. 시스템 구성

```

  오늘 · 공개 · 일지 · 개념 · 신고 · 온보딩
        │ Route Handlers (/api/*)

  users · invites · sessions_auth · judgments · concept_progress · review_schedule

  공공 자료 수집 → 세 판 초안 → 마스킹 → 체크리스트 자동 검사 → 버전 부여 → seed
```

## 2. 스택·배포

- Next.js 16(App Router, Route Handlers), TypeScript, Prisma, Postgres 16. 테스트는 Vitest + Playwright(프론트 e2e는 IfSave 프론트의 설치본 재사용).
- compose 프로젝트 `bokgi`: `bokgi-web`(127.0.0.1:3100), `bokgi-db`(127.0.0.1:5433, 볼륨 `bokgi_pgdata`). beta 스택을 내린 뒤 올린다.
- 공개: Cloudflare 터널 ingress `bokgi.ifsave.com → http://127.0.0.1:3100`. HTTPS는 터널이 끝낸다.
- 환경변수(이름만): `DATABASE_URL`, `SESSION_SECRET`, `INVITE_CODES`(쉼표 구분, 베타용), `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`, `AI_FALLBACK_API_KEY`, `AI_FALLBACK_BASE_URL`, `AI_FALLBACK_MODEL`, `AI_DAILY_CALL_CAP`, `PUBLIC_ORIGIN`.
- 인증: 초대 코드 입력 → 닉네임 → **DB 세션 하나**(`sessions_auth`, 쿠키 `__Host-bokgi_sid`, HttpOnly·Secure·SameSite=Lax, 로그인 때 새 토큰). 코드 소비·가입·세션 생성은 한 트랜잭션. 비밀번호·이메일 없음. 로그아웃과 관리자 재발급 스크립트가 있다. 코드 출처는 `invites` 테이블 하나다(env `INVITE_CODES`는 쓰지 않는다).
- 요청 공통: 비GET은 `Origin === PUBLIC_ORIGIN`과 `application/json`만 받는다(같은 사이트 `*.ifsave.com`의 다른 앱에서 오는 요청을 막기 위해 SameSite만 믿지 않는다). 세션은 미들웨어가 아니라 **핸들러에서** 다시 확인한다.
- 배포: env 검증 → build(이미지 태그 = git sha) → `pg_dump -Fc` → `compose run --rm migrate`(prisma CLI가 든 별도 타깃, `migrate deploy`만) → `up -d` → `/api/health` 대기 → 실패 시 직전 태그로 되돌림. 마이그레이션은 추가형만.
- compose: web `127.0.0.1:3100:3000`, `user: nextjs`, `restart: unless-stopped`, `mem_limit: 512m`, 로그 10m×3(IfSave 프론트 설정 복사). db는 포트 게시 없음, `statement_timeout=15s`. `.dockerignore`에 `.env*`.
- 백업: IfSave 런북의 `pg-backup.sh`(03:00·AES-256·rclone·하트비트)에 bokgi-db를 추가하고 W8 전에 복원 리허설 1회.
- 감시: UptimeRobot → `/api/health`(DB만 확인, AI 제외). IfSave 워치독은 IfSave만 살리므로 고치지 않는다. 로그에 프롬프트 원문·초대 코드·닉네임을 남기지 않는다.

## 3. 데이터 모델

```sql
-- ① 판단 전 (어느 열·jsonb에도 결과급 값이 없다; 판단 시점 절대 날짜는 여기 없다 = case_outcomes.start_date)
cases (id uuid pk, version int, year_public int, sector_public text, size_bucket text,
       horizon_days int, difficulty int, status text, deck_order int not null unique,  -- 결과 균형은 제작 도구가 굳힌 순서
       created_at, reviewed_at);
case_blocks (case_id, version, kind, payload jsonb, pk (case_id, version, kind));   -- kind: flow | numbers | then
concepts (id text pk, branch text, title, body_md, quiz jsonb);                       -- 사례별 연결 문장은 공개 쪽으로

-- ② 공개 뒤 (server-only 모듈만 읽는다)
case_outcomes (case_id, version, company_name, ticker, start_date, end_date, start_price, end_price,
       return_pct, bench_return_pct, sector_return_pct, price_path jsonb, bench_path jsonb, sources jsonb,
       pk (case_id, version));
case_reveal (case_id, version, key_points jsonb, pk (case_id, version));            -- 사후에 중요했던 것, 원문 출처 위치
case_learning_points (case_id, concept_id, rank, link_sentence, pk (case_id, concept_id));

-- 사용자
users (id, nickname, tz text default 'Asia/Seoul', created_at, onboarded_at);
invites (code_hash pk, label, expires_at, used_at, used_by unique);
sessions_auth (token_hash pk, user_id, expires_at, revoked_at);
judgments (id, user_id, case_id, case_version, local_date date not null,
       key_evidence text not null, risk_factor text, direction text not null,
       confidence int not null, recognized bool not null default false, self_check text,
       is_extra bool not null default false, panels_viewed jsonb, gesture jsonb,
       created_at, revealed_at,
       unique (user_id, case_id), index (user_id, created_at desc));               -- 버전은 키에 넣지 않는다
judgment_outcomes (judgment_id pk, relative_pp numeric, state text, hit bool null, scored_at,
       check ((state = 'even') = (hit is null)));
ai_dialogs (id, user_id, case_id, judgment_id, role, template_type, text, guard jsonb, latency_ms, created_at);
ai_usage_daily (day pk, calls);
concept_progress (user_id, concept_id, state, level int, due_on date, quiz_correct, quiz_total, last_seen,
       pk (user_id, concept_id));                                                     -- review_schedule 통합
quiz_attempts (id, user_id, concept_id, correct, via, level_before, client_attempt_id,
       unique (user_id, client_attempt_id));
daily_sessions (user_id, local_date, case_ids uuid[], pk (user_id, local_date));    -- 세트 고정, 카운터는 파생
reports (id, user_id, case_id, case_version, category, note, status, created_at);
events (id, user_id, session_id, event, case_id, case_version, payload jsonb, client_event_id, ts,
       unique (user_id, client_event_id));
```

Prisma 주의: 닫힌 집합(kind·direction·state·branch·self_check)은 Prisma enum, 범위·불변식 CHECK와 부분 인덱스는 `--create-only`로 만든 마이그레이션 SQL에 직접 쓴다. 시각은 `@db.Timestamptz(3)`. jsonb payload는 kind별 zod `.strict()`로 읽고 쓴다. 카드 버전과 uuid는 카드 원본 JSON(저장소에서 버전 관리)에 고정하고 시드는 upsert만 한다(`deleteMany` 금지, `--dry-run` 제공). `card_versions` 테이블은 두지 않는다.

## 4. API

공통: 비GET은 `Origin === PUBLIC_ORIGIN`과 `application/json`만. 세션은 핸들러에서 확인. `/judgments/{id}/*`는 `{id, userId}`로 찾고 남의 것은 404. 오류는 `{error:{code,message}}`(422·409·429 + `Retry-After`). 응답은 `Cache-Control: private, no-store`. 상태 변화(판단·공개·퀴즈·세션)는 서버가 기록하고 클라이언트 이벤트는 UI 이벤트만 보낸다.

| 메서드 | 경로 | 반환 | 규칙 |
|---|---|---|---|
| GET | `/api/me` | 닉네임·온보딩·오늘 세트 | |
| POST | `/api/auth/invite` | 세션 쿠키 | 코드 1회. `CF-Connecting-IP`당 10분 5회, 전체 시간당 30회, 실패 문구는 하나 |
| POST | `/api/auth/logout` | 200 | 세션 폐기 |

## 5. AI 오케스트레이터

| 역할 | 시점 | 컨텍스트에 넣는 것 | 절대 넣지 않는 것 |
|---|---|---|---|
| 질문자 | 공개 전 | 세 판(상대 날짜), 사용자 근거·확신도, 어조 | outcome, 회사명, 절대 날짜 |
| 해설자 | 공개 후 | outcome, 사용자 판단, 학습 포인트 개념 | 문서 밖 원인 단정 요구 |

- 질문자 템플릿 유형 6종(기획안 §8.1). 프롬프트는 유형을 하나 고르고 그 틀로만 두 문장을 쓰게 한다.
- 가드 체인: `numberGuard`(허용 숫자 집합 대조) → `leakFilter`(규칙: 기준일 이후 날짜 표현, 회사·티커·제품명 사전, outcome 수치; 판정 1회: "판단 시점 이후 정보를 담는가") → `labels`(문장 단위 📄/🔍/❓) → 어조 레이어.
- 실패·한도 초과·`AI_ENABLED=false`면 템플릿 질문(유형별 고정 문장 3개씩).
- `lib/ai/*`와 누수 사전은 `import "server-only"`. 사전은 `case_outcomes`에서 서버가 만들고 번들·`public/`에 두지 않는다.
- 질문자 입력은 `toPublicCase()`와 칩 라벨·확신도뿐. 사용자 자유 텍스트·닉네임·신고 메모는 프롬프트에 넣지 않는다.
- 순서: 생성(어조는 시스템 프롬프트) → numberGuard → leakFilter → 라벨. **가드 뒤에 문장을 바꾸는 단계는 없다.**
- 호출은 6초 제한, DB 트랜잭션 밖. 한도는 `ai_usage_daily`(판정 호출 포함)로 세고 재배포에도 유지.
- 기록은 `ai_dialogs`에 유형·가드 결과·지연만. 프롬프트 원문은 로그에 남기지 않는다.

## 6. 카드 제작 파이프라인 (tools/cards)

```
pick_case.py       # 후보(회사·판단 시점·기간) 목록, 결과 균형(앞섬/뒤짐/비슷함) 확인
numbers_from_filings.py  # 공시 원문 → 숫자 판 초안(공시일 ≤ 판단 시점 확인)
then_template.py   # 금리·거시(공개 통계) + 사람이 쓴 이슈 문장(상대 날짜·출처 종류) 조립
flow_index.py      # 판단 시점 100 기준 14점 파생 지수 + 시장 지수(연구 채택 자료는 계산 입력으로만)
outcome.py         # 결과 수익률(배당·분할 반영), 세 상태 계산, 가격 경로 14점
mask.py            # 이름·티커·제품명·절대 날짜 제거(연구 anonymization 재사용)
check_case.py      # 체크리스트 자동 검사: 판단 시점 이후 날짜 0건, 사전 매칭 0건, 공시일 ≤ 기준일, 출처 필수, 배당·분할 반영 플래그
seed.ts            # 통과한 카드만 status=live로 적재, 버전 부여
```

수작업: 사례 선정, 이슈 문장 작성, 학습 포인트 지정, 검토 승인. 목표: 8주차까지 30장(미국 24·국내 6).

## 7. 세션·복습 규칙

- 하루 = 서버가 `users.tz`로 계산한 날짜(베타는 Asia/Seoul 고정). 세션 카드 3장은 미판단 카드 중 `deck_order` 순. 결과 균형(앞섬/뒤짐/비슷함이 연속 3장 같지 않게)은 **제작 도구 `pick_case.py`가 덱 순서로 굳힌다** — 런타임이 결과를 읽으면 안 되고, 규칙 자체가 단서가 되기 때문이다.
- 복습 기한: `due_on`(날짜). 맞히면 level+1(간격 1·3·7·21일), 틀리면 level 0(1일), 기한 전 정답은 level 유지. 하루 2개 상한, 기한 지난 것부터.
- 스트릭: 세션 카드 1장 이상 판단한 날이 연속된 수. 끊겨도 비난 문구 없음.
- 통계(20장 뒤): 근거별 횟수, 확신도 구간별 결과 상태 분포(글), 아는 회사/모르는 회사 비교(글).

## 8. 테스트 계획

| 대상 | 방법 | 통과 기준 |
|---|---|---|
