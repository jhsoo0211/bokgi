# UX 검토(사용자 관점)와 화면 변경

_검토 대상: 워크시트 프로토타입(2026-09-30, 카드 3장·역추적 1장·리포트), 380px 모바일 뷰로 처음 쓰는 사람의 눈으로 끝까지 따라감 · 변경은 `prototype/`에 적용_

## 1. 처음 쓰는 사람이 겪는 것 → 바꾼 것

| 장면 | 겪는 것 | 바꾼 것 | 이유 |
|---|---|---|---|
| 첫 화면 | 바로 '차트/재무/복합' 세그먼트. 무엇을 고르라는지 모른다. 복합은 비활성 | 렌즈 선택 삭제. 온보딩 3장(맞히기 게임이 아니다 / 하루 3장 5분 / 결과는 판단 뒤에만) 뒤 바로 첫 카드 | 첫 결정이 '모르는 개념 고르기'면 이탈한다 |
| 카드 | 재무 숫자가 한 화면에 12개 넘게 나열. 맥락(금리)은 재무 안에 섞여 있다 | 세 판 탭 「흐름」「숫자」「그때」. 기본은 숫자. 판 전환은 기록만 | 정보를 묶어 주면 '어디를 봤는지'를 스스로 알게 된다. 당시 상황을 따로 보여 달라는 요구 |
| 근거 칩 | "PER 38 vs 27" 같은 칩은 왜 중요한지 모르면 고를 수 없다 | 칩에 한 줄 설명(왜 중요?) | 근거 선택이 학습의 첫 단계가 된다 |
| 확신도 | 3이 미리 눌려 있어 그냥 넘어간다 | 기본값 없음. 근거와 확신도를 둘 다 골라야 판단이 열린다 | 보정 지표가 의미를 갖는다 |
| 판단 버튼 | '잘했다/못했다'가 "내 판단이 맞았다"처럼 읽힌다 | "시장보다 앞섰다 / 뒤졌다" | 판단 대상은 회사이고 기준은 시장이다 |
| 아는 회사 | 대형주라 이미 아는데 아는 척하지 말라는 느낌 | 판단 전 "이 회사를 아는 것 같아요" 체크 | 아는 것을 숨기게 하지 않고 기록으로 분리한다 |
| 되돌리기 | 매 카드 2.5초를 기다린다 | 기다림은 유지, "바로 공개" 버튼 추가 | 실수 복구는 남기고 속도는 사용자가 정한다 |
| 공개 | 적중 도장이 먼저 보이고 숫자가 4개. 상대 수익 0.2%p도 적중/실패로 갈린다 | 결과 상태 세 가지(앞섬/뒤짐/비슷함 ±1%p). 회사·기간 → 시장 대비 한 줄 → 경로 → 내 근거 vs 사후에 중요했던 것 → 개념 → 문제 | '맞았다'보다 '무엇이 중요했나'가 먼저 보여야 한다 |
| 색 | 빨강·파랑만으로 결과를 구분 | 부호(+/−)와 도형(▲▼■) 병행 | 색각 대비 |
| 개념·문제 | 카드마다 긴 설명 + 문제 | 개념은 세 문장, 문제 1개. 두 번 맞힌 개념은 공개 화면에서 접힘 | 피로 누적 방지 |
| 리포트 탭 | 처음부터 '잠금'. 눌러도 할 게 없는 탭 | 리포트·역추적 탭 삭제. 하단 탭 = 오늘 · 일지 · 개념 | 죽은 탭은 신뢰를 깎는다 |
| 일지 | 없음(기록을 볼 곳이 없음) | 판단 일지 즉시: 날짜·회사(공개 뒤)·방향·근거·확신도·결과 상태·'알고 판단' 표시 | 진행감은 숫자가 아니라 기록에서 온다 |
| 통계 | 렌즈별 적중률·보정이 큰 글씨 | 일지 안의 접힌 영역, 20장 뒤, 글로 | 적중률을 점수로 만들지 않는다 |
| 세션 | 끝이 없다. 카드가 다 떨어지면 리포트로 튄다 | 오늘 세션 = 3장 + 복습 2개. "오늘은 여기까지" + '한 장 더' | 매일 돌아올 이유와 끝맺음 |
| 신고 | 문서에만 있고 화면에 없다 | 공개 화면에 "정보가 이상해요"(유형 8개 + 메모) | 카드 품질 루프의 입구 |
| 역추적 | 가설 → AI 질문 → 증거 → 투자자 공개가 한 화면에서 길게 이어진다 | MVP 화면에서 제거(2단계). 자료는 보존 | 집중 |

## 2. 화면 구성(MVP)

| 화면 | 핵심 요소 |
|---|---|
| 온보딩(첫 1회) | 3장, '시작' |
| 오늘 | 상단 "오늘 n/3 · 스트릭 k일", 카드 스택(3장 peek), 세 판 탭, 근거 칩(+설명), 위험 칩(선택), 아는 회사 체크, 확신도 5단, 좌우 버튼, 힌트 |
| 공개 | 회사·기간, 시장 대비 한 줄(세 상태 도장), 경로, 내 판단 표, 사후에 중요했던 것, 해설(문장 라벨), 개념 + 문제 1개, 신고 버튼, 다음 카드 |
| 오늘 끝 | 오늘 본 개념 요약, 복습 문제(기한 된 것 ≤2), '한 장 더' |
| 일지 | 판단 목록(최신순), 접힌 통계(20장 뒤), 내보내기·초기화 |
| 개념 | 20개 목록 + 숙련도 상태 + 복습 예정일. 탭하면 설명과 문제 |
| 신고 시트 | 유형 8개 라디오 + 메모 |

## 3. 지켜야 할 규칙(코드 리뷰 기준)

- 판단 전 코드는 결과 자료를 읽지 않는다. 결과색(상승·하락)도 쓰지 않는다. 공개 화면에서만.
- 근거 1개와 확신도를 고르기 전에는 스와이프·버튼이 열리지 않는다. 버튼과 키보드 대체 입력은 항상 있다.
- 스와이프 거리로 확신도를 추정하지 않는다. 제스처 메타는 기록만.
- 적중률을 큰 숫자로 보여 주지 않는다. 비슷함은 적중·실패로 세지 않는다.
- AI 문장은 라벨과 함께 문장 단위로. 추론 문장 옆에 면책 한 줄.

## 4. 접근성

- 터치 타깃 44px, 포커스 링 2px, 색 + 부호 + 도형, `prefers-reduced-motion`이면 스와이프 이탈 애니메이션 없이 즉시 전환.
- 글자 크기는 본문 14/22, 숫자는 `tnum`. 음수 부호는 U+2212.

## 5. 2차 변경 (2026-10-03, 레퍼런스 반영 · 사용자 승인)

| 변경 | 출처 | 학습 중심을 지키는 방식 |
|---|---|---|
| 오늘 화면 맨 위 **입장 띠**: "개념 이해 n/20 · 복습 예정 m개 / 오늘 남은 카드 k장", 스트릭은 작은 글씨 | SLAP의 입장 카드 | 첫 줄이 개념이다. 다음 카드의 학습 포인트는 보여 주지 않는다(결과 암시 방지) |
| 일지 위 **연습 달력**: 연습한 날 점, 복습 예정일 테두리, 오늘 펜 링, "이달 연습 n일 · 복습 n개" | SLAP의 월 달력 | 결과 상태로 칠하지 않는다 |
| 공개 화면 **개념 확인 ○△✕**: "내 근거는 이 개념과 맞았나요?" | Hedge의 원칙 체크 | 원칙 준수가 아니라 개념 확인. 합산하지 않고 일지에 표시만 |
| **해설자 두 묶음**: 이번에 잘 읽은 것 / 다음에 바꿀 것 / 개념 연결(형광펜) | Hedge의 유지·고칠 것 | 개념 연결이 마지막이자 가장 강조 |
| 통계를 **인사이트 카드** 1~3장(횟수만 쓴 한 문장)으로 | SLAP의 패턴 발견 | 비율·적중률 숫자 없음, 20장 뒤에만 |
| **형광펜 밑줄** 토큰: 공개 뒤 개념 제목과 '사후에 중요했던 것'에만 | SLAP의 하이라이트 | 판단 전 화면에는 쓰지 않는다 |

## 6. 남은 UX 질문

1. 세 판 탭의 기본을 '숫자'로 둔 것이 맞는가, 아니면 카드마다 핵심 근거가 있는 판을 기본으로 둘 것인가.
2. 질문자 대화를 카드 3장 중 1장에만 붙여 세션을 5분 안에 묶을 것인가.
3. '한 장 더'를 하루 몇 장까지 허용할 것인가(복습 기억 간격을 해치지 않는 선).
4. 스트릭이 끊겼을 때의 문구(비난 금지, 복귀 유도).
5. 개념 확인 ○△✕을 난이도 1 카드에서도 보여 줄 것인가(프로토타입은 모든 카드에 표시).
