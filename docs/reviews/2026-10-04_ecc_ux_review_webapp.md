# 복기 웹앱 UX 감사 (ecc 체크리스트 + 듀오링고 흐름 렌즈, 2026-10-04)

_대상: `web/`(프로토타입을 옮긴 React·Next.js 16 앱), 목 모드 개발 서버. 적용 스킬: frontend-a11y, make-interfaces-feel-better, click-path-audit, browser-qa, design-system + UI/UX Pro Max 검색 22회(듀오링고식 흐름 5회 포함). 헤드리스 Chromium 380×760(+320×568·430×932, 글자 200%, 긴 문자열, 모션 감소, 느린 네트워크, 터치)에서 화면 17가지 상태의 컨트롤 156개를 쟀다. 초대 화면(실제 API 전용)은 코드만 읽었다. 제품 규칙(판단 전 결과 자료·결과색·형광펜 금지, 근거 1개 + 확신도 게이트, 버튼·키보드 대체 입력, 적중률 숫자 금지, 비슷함 비채점, AI 문장 라벨, 계약·백엔드 불변)은 그대로다._

### 제품 확인이 필요한 결정

1. **공개 순서**: 이번 순서(되짚기 → 결과)를 06 §7 '화면 패턴'의 공개 순서와 §5 표에 옮겨야 한다(문서는 아직 '결과 상태 → 수치 → 경로 → 내 판단 → 사후'). 결과 한 줄은 그대로 첫 화면 안이다.
2. **○△✕를 결과보다 먼저 보게 됨**: 결과를 보기 전에 '내 근거는 이 개념과 맞았나'에 답하게 되어 결과 편향이 줄어드는 쪽이지만, 기존 흐름과 다르다.
3. **스트릭 0일 문구** '오늘 연습하면 스트릭 1일'(02 §6-4 제안 반영).
4. **'다음'이 개념 카드부터 붙는 것**: 듀오링고처럼 처음부터 붙이면 개념·문제를 건너뛰기 쉬워진다고 보고 이렇게 했다.

## 곧 들어올 기능의 자리(이번에 만들지 않음)

- **정보 수준 모드(초급·중급·고급·사용자 지정)**: 설정 단추는 오늘 머리줄(`TodayTop`) 오른쪽 끝, 지금 '판단/결과/복습 i/n' 라벨 옆(주석으로 자리 표시). 시트는 신고 시트의 틀(뒤 화면 inert·Tab 가두기·Esc·초점 복귀)을 공용 `Sheet`로 뽑아 같이 쓰면 된다. 온보딩 넷째 장은 `format.ts ONBOARDING`에 한 장을 더하고 고르기 칸만 그리면 된다(`Onboarding`은 배열 길이대로 돈다). 판의 필드 수는 `CardFace`의 `NumbersBlock`·`ThenBlock`·`FlowBlock`에 수준 값을 넘겨 거르는 자리. 근거 칩이 숨긴 필드를 가리키지 않게 칩도 함께 걸러야 하고, 판단 전 규칙(결과 자료 없음)은 그대로다. 위 '되돌리기 알림 시간'도 같은 시트에 둘 만하다.
- **개념 탭 '길' 보기**: `ConceptsScreen`의 `ConceptList` 자리에서 같은 목록 자료를 갈래 네 개의 단원 길로 그리는 다른 보기(전환은 개념 머리줄 오른쪽 '4개' 자리). 갈래 안 순서·선행 관계는 지금 계약에 없어 필드가 필요하다. 목록에서 상세로 갔다 돌아오면 연 줄로 초점이 돌아오는 처리는 길 보기에도 그대로 쓴다.

## 재지 못한 것

- 실제 화면 읽기 프로그램(VoiceOver·TalkBack) 청취, 실기기(당겨서 새로고침·iOS 안전 영역·탭 강조) — 헤드리스에서는 계산 스타일과 AX 트리만 봤다. CDP는 `aria-valuetext`를 빈 값으로 보고하는데 기준용 slider도 똑같이 비어 있어 도구 한계로 본다(DOM 속성은 있음).
- 크롬의 강제 어둡게 하기(헤드리스에서 흉내 불가 — `color-scheme` 선언만 확인), Core Web Vitals(개발 서버·목 모드라 의미 없음), 시각 회귀(커밋된 기준 사진이 없어 browser-qa 기준으로 INCONCLUSIVE — 전·후 사진은 하네스 결과 폴더에만 있음).
- 실제 API의 오류·시간 초과·오프라인 경로와 초대 화면은 목이 실패하지 않아 코드로만 확인했다(`api.ts`·`errors.ts`·`InviteScreen.tsx`).
- 글자 200%는 모든 글자 크기를 두 배로 바꿔 흉내 냈다(브라우저 확대가 아니라 안드로이드 글꼴 크기에 가까움).
